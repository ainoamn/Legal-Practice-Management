# LEGAL OFFICE AI

منصة لإدارة مكاتب المحاماة، عُمان أولاً. تشمل حالياً الهوية وإدارة المنصة والعمل القانوني والمستندات ومالية المكتب وبوابة الموكل والعقود والوكالات والتراخيص والتقويم ولوحة المهام ضمن النطاق المبين في [LEGAL_OPERATIONS.md](docs/LEGAL_OPERATIONS.md). الوثيقة الاستراتيجية كاملة لم تنفذ بعد، ولا يمثل المستودع منتجاً جاهزاً للاستخدام التجاري. الحالة والقيود في [PROJECT_STATUS.md](PROJECT_STATUS.md).

## التشغيل المحلي

المتطلبات: Node.js 24 LTS، npm، Docker مع محرك عامل.

```powershell
Copy-Item .env.example .env
docker compose up -d
npm ci
npm run db:generate
npm run db:deploy
npm run security:key
npm run dev
```

افتح http://localhost:4310 ثم «إنشاء مكتب». لا توجد حسابات افتراضية أو بيانات قضايا تجريبية. دوّن معرّف المكتب؛ يستخدم مع البريد وكلمة المرور عند الدخول. إعداد دولة عُمان بيانات تهيئة تشغيلية، وليس ادعاءً بصحة قواعد قانونية أو ضريبية. لا ترفع وثائق حقيقية حساسة قبل اكتمال بوابات الإطلاق.

Swagger محلياً http://127.0.0.1:4311/api/docs. الواجهة تمرر الطلبات عبر نفس الأصل إلى Nest. يجب أن تتطابق WEB_ORIGIN مع عنوان المتصفح تماماً. عند استخدام منفذ مختلف، حدّث البيئة وأعد تشغيل API. ملفات `.env` مستبعدة من Git. كلمات المرور المرفقة محلية فقط، ويجب تغييرها في أي بيئة مشتركة.

## إدارة المنصة

مسار الإدارة: http://localhost:4310/admin . حسابات Admin مستقلة عن المكاتب، ولا توجد كلمة مرور افتراضية. أنشئ مالك المنصة مرة واحدة:

```powershell
npm run security:key
npm run admin:bootstrap
```

يطلب bootstrap البريد والاسم وكلمة مرور مخفية من 16 حرفاً على الأقل؛ لا يمرر كلمة المرور عبر معاملات سطر الأوامر ولا يستبدل مالكاً موجوداً. عند أول دخول، يجب تفعيل تطبيق المصادقة قبل فتح الإدارة. أداة المفتاح محلية ولا تستبدل مفتاحاً قائماً. احفظ المفتاح بأمان؛ إدارة الأسرار والمراجعة التشغيلية لازمتان قبل الإنتاج.

الأقسام تعمل عبر قاعدة البيانات: المكاتب والمستخدمون، الباقات وحد المستخدمين، الاشتراكات، فواتير المنصة والتحصيل اليدوي، الصفحات والنشر، الدول والعملات، اسم المنصة ولونها والتسجيل العام، المديرون والصلاحيات، الجلسات وإنهاؤها، التدقيق والمراقبة. حساب `legal_platform` لا يملك قراءة جداول المكاتب الأصلية أو كلمات مرور مستخدميها. التفاصيل في [PLATFORM_ADMIN.md](docs/PLATFORM_ADMIN.md).

الدفع الإلكتروني والبريد الحقيقي غير مرتبطين بمفاتيح حالياً. مالية المكتب لها وحدة مستقلة عن تحصيل اشتراكات المنصة، وتشمل قيوداً متوازنة وأمانات منفصلة. صفحة عامة منشورة تظهر في `/pages/<slug>`؛ المحتوى يعرض كنص آمن. إدارة ملفات الشعار والدعم التشغيلي وموفرو الخدمات المتقدمة ما زالت متبقية.

## المستندات والتخزين المحلي

تحتاج اختبارات المستندات والمتصفح إلى S3 خاص وClamAV بقاعدة توقيعات محدثة وTesseract بالعربية والإنجليزية وPoppler وChromium. في هذا الجهاز جُهزت الأدوات في Ubuntu على WSL، وخادم SeaweedFS 4.52 متوافق مع S3 على المنفذ المحلي 4320. لا يعتمد OCR المحلي على مفتاح خارجي.

```powershell
npm run test:setup
npm run storage:setup
npm run storage:dev
```

أبق خادم التخزين عاملاً في طرفية مستقلة، ثم شغّل التطبيق أو الفحوصات في طرفية أخرى. `storage:setup` يولّد أسراراً منفصلة للتطوير والاختبار داخل الملفات المستبعدة ولا يطبعها أو يستبدل إعداد خادم خارجي. يحتاج `storage:dev` إلى `/usr/local/bin/weed` في Ubuntu. تنزيل CI المثبت والمتحقق من بصمته موثق في `scripts/ci-document-services.sh`؛ تثبيت الأدوات لا يتم تلقائياً بواسطة التطبيق. سجلات التخزين في مجلد مستخدم Ubuntu، والتوقيعات تحدث بخدمة freshclam. الإعداد المحلي مقيد بالـloopback وJWT داخلي ولا يمثل بنية إنتاج موزعة أو مشفرة بالكامل.

اختر «العمل القانوني» لإنشاء الموكل والقضية والمستند. اختر «مالية المكتب» للفواتير والقيود والأمانات. لإنشاء بوابة: أنشئ عضو فريق بدور «الموكل»، واربطه بملف الموكل، ثم انشر القضية والمستند المعتمد كلّاً على حدة. المسار `/portal` مستقل عن Admin.

## البنية والمتابعة

- `apps/api`: الهوية ومساحة المكتب وإدارة المنصة والعمل القانوني والمستندات والمالية وبوابة الموكل.
- `apps/web`: واجهة عربية/إنجليزية وRTL/LTR مع الوضع الداكن.
- `packages/database`: Prisma وmigrations وسياسات PostgreSQL.
- `packages/contracts`: مخططات Zod ومفردات الصلاحيات.
- `docs`: الطلب الكامل والمتطلبات والقرارات والمعمارية وخطة المراحل.
- `tests`: وحدة وتكامل HTTP وPlaywright.

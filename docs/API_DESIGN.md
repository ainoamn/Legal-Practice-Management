# API design

Prefix `/api/v1`; Swagger at `/api/docs` in development only. JSON input parsed by shared strict Zod contracts; unknown fields rejected. Errors `{error:{code,message,requestId}}`. Dates ISO 8601. Paginated lists `{items,total,page,pageSize}` with capped page sizes and allowlisted sort fields. Authentication cookie is never returned in JSON.

Foundation endpoints: `GET health`, `GET countries`, `POST auth/register`, `POST auth/login`, `POST auth/logout`, `GET auth/me`, `GET auth/sessions`, `DELETE auth/sessions/:id`, `POST auth/revoke-others`, `GET/PATCH tenants/current`, `GET/POST users`, `PATCH users/:id`, `GET/POST roles`, `PATCH roles/:id`, `GET permissions`, `GET audit`, `GET dashboard`. Registration selects country from DB, creates office and owner. Login uses email/password plus office slug to resolve membership. Request tenant context comes exclusively from authenticated session. GET never mutates user data.

Swagger describes foundation DTO schemas and cookie security; all mutation routes require allowed Origin and JSON. Deletes are used only for session revocation. Members are suspended rather than physically deleted. Public registration creates no financial subscription promises.

Reserved future office groups: clients, matters, hearings, courts, documents, drafts, contracts, power-of-attorney, tasks, calendar, finance, invoices, payments, expenses, notifications, ai, reports, subscriptions. They are not mounted until their modules work end to end; platform billing is separate from these office routes.
Platform is now mounted as described below. The other reserved groups remain unmounted until their implementations exist.

Additional auth routes: `GET auth/capabilities`; `GET auth/mfa`; `POST auth/mfa/setup` (current password), `POST auth/mfa/confirm` (fresh 6-digit code, returns recovery codes once), `POST auth/mfa/disable` (password + fresh factor); `POST auth/password/forgot` (email + office slug, generic response); `POST auth/password/reset` (one-use token + new password). Login accepts optional `factor`; correct credentials on an MFA account return MFA_REQUIRED until a factor is supplied. All secret-bearing responses are no-store. No API exposes recovery-email tokens.

Platform routes: `/platform/auth/{login,me,logout,mfa/setup,mfa/confirm,revoke-others}` use independent credentials and a Strict path-scoped cookie. Protected `/platform/{overview,tenants,users,plans,subscriptions,invoices,payments,pages,countries,settings,admins,audit,monitoring,sessions}` provide actual policy-checked operations. Mutations use strict shared Zod contracts and administrator audit. Owner provisioning is local-only. Page lists and metadata/billing/admin lists paginate at max 100; published-only public endpoints are `/public/settings`, `/public/pages` and `/public/pages/:slug`. Financial amounts enter as decimal strings and are stored as validated minor units. There is no public endpoint for platform registration, authentication secrets, card processing or legal-file access.

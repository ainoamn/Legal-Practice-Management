# Test strategy

Run lint, strict typecheck, unit, PostgreSQL/Redis HTTP integration, Playwright end-to-end, production builds and dependency audit. Integration data is created through real registration; each test office has independent users/sessions. Never seed demo legal/financial data in production.

Required foundation cases: atomic registration and duplicate email/slug handling; Argon2 verification and generic login errors; server-authorized office selection; expiry/logout/revocation; CSRF origin and unknown-input rejection; two tenants cannot read/update each other's member/role IDs; direct SQL without tenant returns zero rows; composite FKs reject cross-tenant roles/branches; DB runtime cannot edit audit; restricted accountant/client/lawyer cannot manage team; role subset delegation and owner protections; suspend removes access immediately; pagination and real dashboard counts; responsive Arabic/English forms and persistent writes across login.

Test runtime must use non-superuser DB credentials; migration setup uses separate owner. PostgreSQL RLS tests are meaningful only on real PostgreSQL; no in-memory replacement is accepted as isolation proof. No security check is skipped to obtain green output. E2E uses production build through same-origin proxy. Docker unavailable is a documented blocker rather than a passing test.

Later acceptance maps to all 25 final request criteria and each legal/finance/AI/file flow. Additional gates: malicious uploads, download IDOR, record ACLs, finance ledger reconciliation, signed webhook idempotency, subscription race tests, RAG injection/citations, restore drill, load and external security review.

Implemented additional suites now cover matter assignment revocation and raw SQL scope, cross-firm legal references, optimistic edits, hearing overlap, matter quotas, durable reminders, actual S3/ClamAV/OCR/file hashes, blocked malware and disguised files, review/approval/history/export, invoice posting and simultaneous overcollection, SQL journal balance and immutability, isolated client funds, finance-only projections, portal published-field projections, file revocation after a new draft and client-link revocation. Portal file fixtures isolate authorization tests; they do not replace the separate real storage/scanner/OCR suite. Browser flows cover each new unit, Arabic/English and mobile, including full client login/redirect/link/publication/communication.

Run npm run check with the private S3 service and required native tools available. Never run separate suites in parallel against the same test DB/Redis queue; the suite runner serializes files. New image builds and workflow definitions are not evidence that Docker/remote CI passed. External penetration/load, backup restore, real email/payment/AI and legal review gates remain outstanding.

## Isolated local tests

Instrument tests additionally cover exact 20-digit amounts, assignment and tenant isolation, approval grants, optimistic edits preserving omitted defaults, agency requirements, cross-client source rejection, pinned approved versions after later document drafts, obligation completion, reminder cancellation/acknowledgment, reassignment revocation and bounded parser errors. Calendar tests cover civil-day DST boundaries, leap years, midnight-spanning events, task range edges, SQL isolation, bilingual mobile views and persistent task-board changes.

`npm run test:setup` creates a local `_test` database without deleting one, deploys migrations and writes ignored `.env.test` with separate runtime URLs, Redis DB 1 and a random MFA key. Vitest setupFiles and Playwright load it before application imports; integration fixtures require LEGAL_TEST_ENV=1. CI uses a fresh legal_test database and a fixture-only key. Tests therefore no longer create platform owners or change branding in the development workspace.

Platform tests cover mandatory enrollment, cookie/DB-role separation, projections, pagination, user quotas, read-only firms, disabled users, currency precision, concurrent receipts, immutable history, published-only safe CMS, settings, restricted operators and session revocation. Browser tests use real forms, balances and published pages, then switch to a less privileged operator in the same browser to detect stale authorization caches. Mail calls remain mocked; these tests do not verify real delivery.
